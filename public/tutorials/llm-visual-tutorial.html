00ORIENTATION
Start here · 先建立地图

一台会预测下一个 token 的概率机器

大语言模型并没有一个装满句子的数据库。它做的是：读入上下文，在每一个位置计算词表上所有 token 的概率，选一个，接上去，再算下一个。整条链路可以拆成七步，后面的每一章都会把其中一步放大。

One sentence to keep

模型不是在“查找”答案，而是在“续写”一个在统计上合理的未来。理解这句话，你就拿到了后续所有机制的钥匙：概率从哪来（训练）、概率如何被塑形（对齐）、如何从概率里选 token（解码）、以及如何花更多计算让概率更可靠（推理模型）。

01TOKENIZATION
Step 1 · 文本 → 离散符号

模型看不见文字，只看得见 token

第一步不是“理解”，而是把字符串切成词表里已有的片段。切分方式决定了模型读一段话要花多少 token、能看多长的上下文，也决定了它会不会把数字和代码切得支离破碎。

直觉上，中文按字、英文按词似乎很自然。但真实的分词器（tokenizer）既不按字也不按词，而是用 BPE（Byte Pair Encoding） 一类算法，从语料里统计哪些字节片段经常一起出现，把高频组合逐步合并成 token。结果是：常见词可能是一个 token，罕见词会被拆成几个子词，空格、标点、换行也各自有编号。

这带来一个很重要的工程事实：token 不等于字，也不等于词。同一句话在不同模型里可能得到不同的 token 数；中文通常比英文更“费 token”；代码里的缩进和符号也会被单独编码。上下文窗口、计费、生成速度，全都按 token 计算。

Why subwords

词表大小与序列长度的折中

如果每个字一个 token，词表很小，但序列很长；如果每个词一个 token，序列短，但词表爆炸且永远覆盖不了新词。子词处在中间：用有限词表覆盖开放文本，让常见片段保持短。

un+believ+able →unbelievable
Why it matters

每一个 token 都要付账

上下文：窗口按 token 计数，不是按字数。
成本：API 按输入 / 输出 token 计费。
速度：自回归生成一次一个 token，越长越慢。
能力：数字被拆碎时，算术与精确复制会更困难。

常见误解

“模型认识这个词，所以它一定懂这个词。”不一定。token 只是编号，语义来自训练后向量与上下文的组合。一个 token 也可以承载多个字符、半个单词，甚至一段空白。分词器与模型是分开训练、分开发布的——换 tokenizer 就等于换了一套“字母表”。

02EMBEDDING
Step 2 · 编号 → 坐标

把 token 放进一个可以计算的空间

编号本身没有大小关系，42 不比 7 更“大”。模型需要的是可学习的向量：把每个 token 映射到 d 维空间中的一个点，让语义关系变成方向、距离和夹角。

猫
VECTOR · [ 0.82, 0.41, … ]

“猫”和“狗”在语义空间里更靠近，和“国王”更远。模型不是把含义写进某一个维度，而是把它分散在成千上万个方向上。

国王 − 男人 + 女人 ≈ 女王
NEAREST NEIGHBORS · 示意
小狗猫咪兔子宠物

把 token 编号变成向量的操作，本质是一次查表：词表里每个 token 对应一个可训练的行向量 E[id]。这个矩阵通常有 5 万到 20 多万行、几千到上万列。查表之后，每个 token 变成了一个 d 维向量，序列就变成了一个 T × d 的矩阵。

但查表得到的向量是“脱离上下文”的：同一个“苹果”，在“吃苹果”和“苹果发布会”里初始表示相同。真正让表示随语境变化的是后面的注意力层。另一个缺口是顺序：向量本身不知道谁在前谁在后，所以还要注入位置信息。现代模型最常用的方案是 RoPE，我们会在第 08 章拆开看。

xt=E[id(wt)]+pt 查表 + 位置
∿

分布式表示

一个概念不由单个维度表示，而由很多维的组合模式表示。这让“相似”可以连续变化，而不是非黑即白。

∠

用余弦看相似

两个向量的夹角越小，方向越接近。模型内部大量使用点积/余弦来衡量“相关性”，这也是注意力的计算基础。

#

二维只是示意

真实嵌入维度常在 2,000–12,000。图中位置是为教学摆放的投影，不代表真实坐标；类比箭头也不是精确等式。

Takeaway

语言模型的第一层“理解”，是把符号变成几何。一旦变成向量，语义相似、类比关系、类别结构就可以用线性代数操作；而上下文相关的含义，则要在注意力层里被重新计算。

03ATTENTION
Step 3 · 让 token 互相看见

注意力：每个词都在决定“该看谁”

如果每个 token 都只带着自己的向量往前跑，模型永远无法处理指代、语法和长距离依赖。注意力机制让每个位置向全上下文发问：我现在需要什么信息？谁手里有？然后把信息加权搬运过来。

注意力用三个角色来描述这次信息交换。Query（Q）是当前位置发出的“检索请求”；Key（K）是每个位置挂出的“内容标签”；Value（V）才是真正被取走的信息。用 Q 和每个 K 做点积，得到相关性分数；softmax 归一化成权重；再用权重对 V 加权求和。

把它想成一次很高效的会议：每个人先写下自己需要什么（Q），再听所有人报出关键词（K）。谁的关键词和你需求最匹配，你就多听谁的内容（V）。关键在于，这套 Q/K/V 都是学出来的，不是人工规则。

Why scale

为什么要除以 √dₖ？

维度越高，点积的方差越大，softmax 越容易变得极端：一个位置接近 1，其余接近 0，梯度几乎消失。除以 √dₖ 把分数拉回稳定区间，让注意力可以平滑地分配。

Causal mask

为什么不能看未来？

自回归生成时，第 t 个位置只能依赖前 t 个 token。训练时把右上角（未来位置）的分数设为 −∞，softmax 后权重为 0。否则模型会“偷看答案”，训练损失好看但推理时崩掉。

真实模型不会只有一组 Q/K/V，而是并行做很多组，叫多头注意力（Multi-Head Attention）。每个头有自己的投影矩阵，可以在不同的子空间里关注不同关系；最后把各头结果拼接、再投影回模型维度。你可以把它理解为：同一段文字，同时用几套不同的“问题”去检索。

HEAD A · SYNTAX

主谓宾、修饰关系。比如“红色的苹果”中，形容词指向名词。

HEAD B · COREFERENCE

代词回指。“它”指向“猫”，“他们”指向前面出现的一群人。

HEAD C · SEMANTICS

主题与事实关联。提到“巴黎”时，把“法国首都”这一背景拉进来。

Takeaway

注意力不是“解释性高亮”，而是模型的计算本身。它决定了每个位置在这一层能读到什么。所谓“上下文窗口”，本质上就是这个注意力可以覆盖的范围；而“长上下文变笨”，很大程度上是注意力在长距离上分配得不够好。

04TRANSFORMER
Step 4 · 把算子组装成网络

Transformer：一层一层地改写表示

注意力负责“横向”交换信息，前馈网络负责“纵向”加工每个位置。两者用残差连接串起来，堆叠几十层，就构成了现代大语言模型的主体。同一个积木重复 N 次，但每一层学到的功能并不相同。

一层 Transformer 可以写成两个“加法”：先做注意力，再把结果加回原向量；再做前馈网络，再把结果加回去。这个看似简单的结构有两个关键好处：残差连接让梯度和信息可以跨层直达，深层网络才训得动；Pre-Norm（先归一化再进子层）让训练更稳定，几乎是现代模型的默认选择。

STEP 01 / 06 · NORMALIZE
RMSNorm：先把数值尺度稳住

深层网络里，向量的数值可能越来越大或越来越小。RMSNorm 用均方根缩放每个 token 的向量，不改变方向，只把尺度拉回稳定范围。它不做均值中心化，比 LayerNorm 少一次计算，也更适合大规模训练。

RMSNorm(x) = x / sqrt(mean(x²) + ε) · γ
现代 decoder-only 架构通常使用 Pre-Norm + RMSNorm图中省略 dropout、bias 等细节
x←x+Attn(RMSNorm(x))     x←x+FFN(RMSNorm(x)) Pre-Norm 残差块

前馈网络（FFN）常被描述为“逐 token 的两层 MLP”：先把维度升高，做非线性变换，再压回原维度。现代模型多用 SwiGLU 门控：一条支路产生候选内容，另一条支路产生门控信号，逐元素相乘。研究发现，FFN 参数量占了模型的大部分，它更像一个分布式的“键值记忆”，存储事实、模板和模式。

还有一个值得记住的视角：残差流（residual stream）是一条贯穿所有层的信息高速公路。注意力从这条流里读取信息、写入新信息；FFN 也不断读取和改写。每一层不是把表示彻底替换，而是在原有基础上做增量修改。这解释了为什么大模型可以“中间层做语法、后层做语义”，也解释了为什么残差连接如此重要。

Normalization

为什么是 RMSNorm？

只按均方根缩放，不减去均值，计算更简单，数值行为稳定。对超大模型，省下的归一化开销和通信量都很可观。

Residual stream

一条共享的“黑板”

所有层读写同一条残差流。注意力负责 token 间路由，FFN 负责逐位置加工。增量写入让深层网络更容易优化。

Depth

层数买到什么？

更多层通常带来更强的组合与抽象能力，但也更难训练、更慢。现代模型常在 30–100+ 层之间，并配合并行策略与稳定性技巧。

Takeaway

Transformer 的强大不来自某个神秘算子，而来自“可堆叠的通用计算单元”。注意力让信息在位置之间流动，FFN 对每个位置做深度加工，残差让梯度与信息畅通，归一化让深层训练不发散。理解了这一层，MoE、MLA、FlashAttention 都只是在这套骨架上的工程替换。

05PRETRAINING
Step 5 · 从数据中获得知识

预训练：把“下一个 token”做到极致

有了架构，模型还是一张随机初始化的网。预训练用海量文本做自监督学习：遮住后文，让模型预测下一个 token。没有人工标注，却能逼迫模型学会语法、事实、推理模式与世界的统计规律。

训练样本的构造简单得惊人：一段文本，每个位置都提供一个“前文 → 下一个 token”的训练信号。模型输出词表上的概率分布，真实 token 的概率越高，交叉熵损失越小。反向传播只做一件事：调整参数，让正确 token 的概率稍微高一点。重复数万亿次，能力就从中涌现。

“预测下一个 token”之所以能学到远超填空的能力，是因为要准确预测后文，模型必须隐式地建模语法结构、实体关系、因果链条、代码执行结果，甚至对话意图。但也要注意：预训练目标只奖励“像训练数据一样续写”，它不天然保证有用、诚实或安全。这为下一章的对齐埋下伏笔。

Data is the moat

数据 Pipeline 比想象中更脏、更贵

网页、书籍、代码、论文、对话……原始语料要先经过抽取、去重、质量过滤、语言识别、隐私清洗、毒性过滤，再按领域配比混合。高质量数据往往被重复训练多轮（epoch），低质量数据宁可丢掉。

采集→清洗→去重→过滤→配比→tokenize→shuffle

一个反直觉的事实：数据质量对最终能力的影响，常常大于架构微调。

预训练的规模不是“越大越好”这么简单。2022 年的 Chinchilla 研究指出：在固定计算预算下，参数量和数据量应该同步增长，大约每个参数配 20 个训练 token 更划算。但现代模型为了降低推理成本，常常主动“过训练”——用远多于 20 token/参数的语料训练一个较小的模型，让它在部署时更便宜。这被称为 inference-optimal，而不是 compute-optimal。

Scaling law

损失随规模平滑下降

在很大范围内，测试损失与参数量、数据量、计算量呈幂律关系。它让研究者可以先用小模型预测大模型的表现。

Chinchilla

不要只堆参数

同样的算力，参数和数据要平衡。只增大模型而数据不足，会浪费计算；只堆数据而模型太小，容量又不够。

Emergence

能力不是线性长出来的

某些能力在规模跨过阈值后突然变好。但“涌现”也部分取决于评测指标：连续指标可能早就缓慢改善了。

Transition

预训练让模型“会续写”，但不等于“会当助手”。你问它“如何做番茄炒蛋”，它可能续写出一篇菜谱网页、一段论坛争论，甚至继续编造你的下一句话。下一步，我们要把“续写者”塑造成“遵循指令、符合偏好”的助手。

06ALIGNMENT
Step 6 · 从“会续写”到“会协作”

对齐：教模型成为你想要的助手

预训练模型是一个极其丰富的“文本续写器”，但它不知道什么时候该回答问题、什么时候该拒绝、什么样的回答更有帮助。对齐阶段用示范与偏好，把这种行为分布重新塑形。

对齐通常分两步。第一步是 SFT（监督微调）：用高质量“指令 → 回答”样本继续训练，让模型学会对话格式、遵循指令、在合适的时候结束。第二步是偏好优化：让人类（或 AI）对同一问题的多个回答排序，训练模型更倾向被偏好的回答、更少产出被拒绝的回答。

这里最重要的认知是：对齐主要改变“怎么回答”，而不是“知道什么”。它可以把已有知识组织得更有用，也可以抑制有害表达；但它很难可靠地注入预训练中完全不存在的新知识。需要新知识时，检索（RAG）或工具通常更靠谱。

安全与帮助的张力

过度安全会让模型变得无用，过度迎合又会带来谄媚与风险。对齐不是一次性任务，而是持续的目标权衡。

↯

奖励黑客

模型会寻找奖励模型的漏洞：更长、更自信、更讨喜，并不等于更正确。参考模型约束与高质量偏好数据是常见防线。

Important distinction

SFT 教“格式与行为”，偏好优化教“取舍与风格”，预训练提供“知识与能力”。把三者混为一谈，就会误以为“再微调一下”能解决所有事实错误。事实上，微调更擅长改变表达方式，不擅长可靠地写入新知识；而且小数据微调还可能带来灾难性遗忘。

07DECODING
Step 7 · 概率 → 具体回答

解码：同一句话，为什么每次都不一样？

模型输出的是词表上的概率分布，不是一句话。选择哪个 token，由解码策略决定：贪心、温度、top-k、top-p……它们不改变模型的知识，却深刻影响回答的稳定度、创造性与多样性。

最直接的做法是每次选概率最高的 token（贪心解码），确定、稳定，但容易重复和乏味。另一种极端是纯粹按概率随机采样，创意更多，却可能跑题。实际系统通常在两者之间：用温度改变分布的陡峭程度，再用 top-k / top-p 截掉长尾的低质量候选。

把所有 logits 变成概率的标准操作是 softmax。温度 T 在 softmax 之前缩放 logits：T < 1 让分布更尖锐，T > 1 让分布更平坦。注意，温度不是“创造力旋钮”这么简单——它同时放大了低概率错误的风险。

Greedy

每次选最大概率

适合事实问答、代码补全等需要确定性的任务。缺点是容易重复、陷入套话，也不会探索“第二条好答案”。

Temperature

把分布压尖或摊平

T→0 接近贪心；T=1 保持模型原始分布；T>1 更随机。它不增加信息，只是重新分配置信度。

Top-k / Top-p

截掉长尾

top-k 固定保留前 k 个；top-p 保留累计概率达到 p 的最小集合。后者能随分布形状自适应，通常更常用。

Engineering reality

线上推理不只是“一次前向”。KV Cache 缓存历史 token 的 Key/Value，避免每生成一个词都重算整段上下文；连续批处理（continuous batching）把不同用户的请求拼在一起；投机解码（speculative decoding）用一个小模型先草拟多个 token，再让大模型一次验证；量化（INT8 / INT4、GPTQ / AWQ）则把权重或激活压到更低比特，以少量精度换显存与吞吐。这些工程优化决定了产品能不能便宜、快速地跑起来。

08MODERN STACK
2023–2025 · 同样的骨架，更强的工程

现代架构：更长的上下文，更低的成本

Transformer 的骨架没变，但现代模型在四个地方做了关键替换：用 RoPE 表示位置，用 GQA / MLA 压缩 KV Cache，用 MoE 解耦参数量与计算量，用 FlashAttention 把显存访问变成瓶颈优化对象。

这些方法解决的是同一个矛盾：我们想要更大的模型、更长的上下文，但显存、带宽和推理成本不能无限上涨。理解它们的关键，不是背缩写，而是看清各自在优化哪一项资源——位置外推、KV 缓存、激活计算、HBM 读写。

把“第几个位置”编码成旋转

RoPE 不是把位置向量加到 word embedding 上，而是对 Q、K 按位置旋转一个角度。位置越靠后，旋转越多。两个 token 的 Q·K 内积只依赖它们的相对位置差，而不是绝对位置。

这个性质让模型更容易外推到更长上下文；再配合位置插值、NTK 缩放或 YaRN，可以把训练时的 8K 窗口扩展到 128K 甚至更长。

推理时，KV Cache 才是显存黑洞

自回归生成要缓存历史 token 的 K/V。多头注意力里每个 Q head 都有自己的 K/V，上下文一长，缓存会迅速吃掉显存。GQA 让多个 Q head 共享一组 K/V；MQA 更极端，所有 Q 共享一组。

MLA（DeepSeek-V2 提出）走另一条路：把 K/V 压缩到一个低秩潜变量，推理时再吸收投影。它比 GQA 更复杂，但能把 KV Cache 压到 MHA 的约 6.7%，同时保留较强的表达能力。

参数量 ≠ 计算量

MoE 把 FFN 拆成很多“专家”，路由器为每个 token 只选少数几个。这样模型可以拥有巨大的总参数容量，但每个 token 的前向计算只经过少数专家，计算成本接近一个小得多的稠密模型。

代价是：路由需要负载均衡，专家并行带来通信开销，训练更复杂；微调时也容易出现专家利用不均。

不改变结果，只改变数据怎么流动

朴素注意力会显式构造一个 T × T 的注意力矩阵，再反复把它写回显存。上下文一长，显存占用和 HBM 读写都会爆炸。FlashAttention 把 Q/K/V 切成块，在 SRAM 里分块计算并用“在线 softmax”累积结果，从不落地完整的 T×T 矩阵。

它仍然是精确注意力，不是近似；计算复杂度仍是 O(T²)，但显存从 O(T²) 降到 O(T)，HBM 访问大幅减少。FlashAttention-2/3 进一步优化了并行与 GPU 特性，是长上下文训练能跑起来的基础设施。

09REASONING
2024–2025 · 用推理计算换准确率

推理模型：让模型“多想几步”

传统对话模型拿到问题就直接生成答案；推理模型会先生成一段更长的思考过程，再给出结论。训练方式也从“模仿人类答案”转向“用可验证的奖励，强化能得出正确答案的思考路径”。

为什么“多想”会变强？因为很多问题无法在一次前向传播中完成。模型需要在中间步骤里做分解、试错、验算，把复杂问题拆成可管理的子问题。生成更多 token，等于给模型更多串行计算的机会。这就是 test-time compute（推理时计算）的核心。

但仅仅让模型“写长一点”没用。真正有效的是用强化学习去筛选：哪些思考过程最终得到了正确答案，哪些没有。对于数学、代码、逻辑这类可以自动验证的任务，我们可以用规则或单元测试给出奖励，而不需要人类逐条打分。这条路线通常被称为 RLVR（Reinforcement Learning with Verifiable Rewards）。

Test-time compute

推理时计算的三种花法

更长 CoT：让模型写更多中间步骤。
多次采样：生成多条候选，再投票或重排。
搜索：在步骤级别展开、评估、回溯。三者可以叠加。

The trade-off

准确率、延迟与成本

推理 token 会直接变成延迟和账单。产品要在“足够好”处停下：简单问题快速直答，困难问题才升级到长思考，这就是自适应推理 / 路由。

RLVR 最常见的高效算法之一是 GRPO（Group Relative Policy Optimization）。它不训练一个单独的价值网络（critic），而是对同一个问题采样一组答案，用这组答案的相对好坏来估计优势：高于组平均的答案被强化，低于组平均的被抑制。这样省掉了 critic，训练更轻，也更适合“同一道题生成多条解法”的推理场景。

01 · SAMPLE
同一问题采样 G 个回答
02 · VERIFY
规则 / 测试给出 0–1 奖励
03 · NORMALIZE
组内减均值、除标准差
04 · UPDATE
PPO 式裁剪目标更新策略
05 · REPEAT
更强策略 → 更难样本
Ai=(ri−mean(r)) / std(r) 组内相对优势，无需 critic
RLHF · 主观偏好

奖励来自人类/AI 对回答的比较，适合“有帮助、礼貌、安全”等难以自动验证的目标。

RLVR · 可验证奖励

奖励来自答案是否正确、代码是否通过测试、格式是否合法。信号客观，但只覆盖可验证任务。

2024 年的 o1 系列让“推理时扩展”成为公开范式；2025 年的 DeepSeek-R1 进一步展示了：纯强化学习可以让模型自发长出反思、验算和长链推理；再加入少量冷启动数据与拒绝采样微调，可以把这种能力做得更可读、更稳定；最后把长思考能力蒸馏到小模型，能显著提升小模型的推理表现。另一条路线是过程奖励模型（PRM），对每一步而不是只对最终答案打分，但标注成本更高。

Critical lens

“思考过程”不一定是模型真实的内部计算。模型可能生成一段看起来合理、实际上与最终答案无关的解释；也可能在简单题上反复检查，浪费大量 token。评测时要区分“答案正确”“过程可信”“成本可接受”三件事。对高风险场景，外部验证与工具执行仍然不可替代。

RAG、Agent 与多模态：把能力接进现实

一个模型再强，也不知道你公司昨天的会议纪要，不能替你发邮件，也看不见屏幕。产品化的关键，是在模型外面加一圈系统：检索、工具、记忆、多模态编码与评测。

先破除一个常见误区：“上下文窗口够长，就不需要 RAG 了”。长上下文确实能塞下更多资料，但把整个知识库都塞进去既贵又慢，还会被无关内容干扰（context rot）。检索的价值不只是“塞得下”，更是在正确的时候，把正确的信息放到模型面前。

Context engineering

上下文是一块有限的工作台

系统提示、工具定义、检索文档、对话历史、记忆、用户输入，全都在争夺同一个窗口。把什么放进去、以什么顺序放、何时压缩，已经成为独立于“提示词”的工程问题。

QUESTION 01 · ATTENTION
缩放点积注意力里，为什么要除以 √dₖ？
答案：B。维度越高点积方差越大，除以 √dₖ 把分数拉回稳定区间。归一化由 softmax 完成；因果掩码是另一件事。
QUESTION 02 · MODERN STACK
GQA 和 MLA 最直接解决的是什么问题？
答案：C。GQA 让多个 Query head 共享 KV；MLA 把 KV 压成低秩潜变量。它们都在降低缓存与带宽，不改变“注意力”的基本作用。
QUESTION 03 · REASONING
RLVR 中的“可验证奖励”通常来自哪里？
答案：B。RLVR 用可自动判定的信号做奖励，典型是数学答案匹配和代码测试。人类逐步打分更接近过程奖励模型（PRM），成本高得多。

Glossary · 随手查
Logits / Softmax

Logits 是模型最后一层输出的未归一化分数；softmax 把它们变成总和为 1 的概率。温度就在 softmax 之前作用。

KV Cache

自回归生成时缓存历史 token 的 Key/Value，避免重复计算。它随上下文长度、层数、头数线性增长，是长上下文推理的主要显存开销。

MoE

混合专家。FFN 被拆成多个专家，路由器为每个 token 选择少数几个，实现“大参数量、小激活计算”。

MLA

Multi-head Latent Attention，DeepSeek-V2 提出的注意力变体，用低秩压缩表示 K/V，显著降低 KV Cache。

RLHF / DPO

RLHF 用奖励模型 + 强化学习优化偏好；DPO 直接把偏好对写进损失，省掉显式奖励模型。两者都依赖参考模型约束。

RLVR / GRPO

RLVR 用可验证奖励训练推理；GRPO 用同题多答案的组内相对优势替代 critic，降低强化学习成本。

Test-time compute

推理时通过更长思维链、多次采样或搜索来换取更高准确率。收益通常递减，需要与延迟、成本权衡。

RAG

检索增强生成。先检索外部知识，再把相关内容放进上下文，让模型基于证据回答，并可给出引用。

One last thing

大语言模型不是“把知识压缩进参数”这么简单，而是一整套从数据到概率、从概率到行为、从行为到系统的工程。当你看新闻里的新方法时，可以连续问四个问题：它改了哪一层？省的是显存、计算还是数据？代价转移到哪里？它改变的是训练目标，还是推理策略？能回答这四个问题，你就不会被缩写淹没。
