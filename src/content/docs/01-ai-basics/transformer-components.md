> 这篇不是教你推公式，而是给你一张"组件-资源画像表"：每个组件吃什么资源、有什么变体、对应哪些优化技术。

## Self-Attention：计算和显存的双料大户

机制一句话：每个 token 用自己的 Query 去和所有 token 的 Key 算相关度，加权汇聚 Value。

Infra 画像：

- 计算量 O(N²)：序列长度翻倍，注意力计算翻四倍。
- KV Cache：推理时显存第一大户（公式见 Transformer 直觉一文）。
- 对应优化：FlashAttention（IO 感知）、GQA/MQA/MLA（砍 KV 头）、滑动窗口（砍上下文）。

## FFN：参数仓库

机制一句话：对每个 token 独立做"放大 → 非线性 → 缩回"的两层矩阵变换，中间维度通常是隐层的 4 倍左右。

Infra 画像：

- 占模型总参数约 2/3——权重大头在这。
- 计算是规整的大矩阵乘，Tensor Core 最爱，GPU 利用率最高的部分。
- MoE 就是把它改造成"很多个专家 FFN + 路由器"——参数量暴涨但计算量可控。

## 位置编码：RoPE 为什么统治了业界

机制问题：注意力本身不包含顺序信息，必须额外注入位置。

主流答案 RoPE（旋转位置编码）：把位置信息编码成对 Q/K 向量的旋转变换，让"相对距离"自然体现在点积里。

Infra 画像：

- 计算开销可忽略，但**上下文外推是工程活**：训练 8K 直接上 128K 会崩，需要位置插值/YaRN 这类外推技巧。
- 运维相关点：max_model_len 配置、长上下文评测必须覆盖位置外推区。

## 归一化与残差：稳定性的地基

- 现代模型用 **RMSNorm**（LayerNorm 的精简版，去掉均值中心化）且放在子层**之前**（Pre-Norm）——训练深层模型不炸的关键工程选择。
- 残差连接让梯度有"高速公路"，百层网络才训得动。

Infra 画像：计算量小，但逐元素操作多——是算子融合的主要对象（torch.compile/Triton 融合的常客）。

## 组件-优化对照速查表 ★

| 组件 | 资源画像 | 主要优化技术 |
| --- | --- | --- |
| Attention | 计算 O(N²)、KV 显存 | FlashAttention、GQA/MLA、PagedAttention |
| FFN | 参数占 2/3 | 量化、MoE、TP 切分 |
| 位置编码 | 几乎免费 | RoPE 外推（YaRN/插值） |
| 归一化/残差 | 逐元素操作多 | 算子融合、CUDA Graph |
| Embedding/输出层 | 词表维度大矩阵 | 词表并行、输出采样优化 |

## 面试串联

被问"Transformer 哪里最耗资源"：训练答 FFN（参数量）+ 注意力（长序列）；推理答 KV Cache（显存）+ Decode 搬权重（带宽）；然后每个都能接出对应的优化技术——这条链就是 AI Infra 面试的主线。
