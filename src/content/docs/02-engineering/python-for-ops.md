> 你的目标不是成为 Python 专家，而是达到"能写可靠的服务脚本、能读懂 AI 代码"的水平。这个目标 2-3 周可达。

## 能力对照：你已经会什么

| Shell 里的你 | Python 里的对应 | 学习优先级 |
| --- | --- | --- |
| 管道 `a \| b \| c` | 函数组合、生成器链 | 高 |
| `for f in *.log` | `for` 循环 + `pathlib` | 高 |
| `curl` + `jq` | `httpx`/`requests` + json | 高 |
| crontab + 脚本 | `asyncio` 任务、调度库 | 中 |
| awk/sed 文本处理 | 字符串方法、正则、 pandas | 中 |
| 并发 `&` + wait | `asyncio.gather` / 线程池 | 高（AI 场景全是并发） |

## 工程必需的 20% 清单

按这个顺序学，别按教科书顺序：

1. **虚拟环境**：`uv` 或 `python -m venv`——AI 项目的依赖地狱比你想的凶，环境隔离是第一天就要养成的习惯。
2. **类型提示（type hints）**：`def fetch(url: str) -> dict:`——可读性和 IDE 补全的命脉，团队协作必备。
3. **异常处理与重试**：`try/except`、指数退避。AI 调用全是网络请求，可靠性模式和服务治理完全一样。
4. **异步 IO**：`async/await`、`asyncio.gather`——LLM 调用动辄数秒，不会异步就写不出及格的 AI 工具。
5. **日志**：`logging` 模块，别再用 `print` 调试。结构化日志是你未来做 LLM 可观测性的基础。
6. **测试**：`pytest` 写最小用例——AI 代码的回归只能靠测试守。

## 刻意跳过的内容

类和元编程的奇技、装饰器黑魔法、GC 细节、C 扩展——用到再学。你的时间预算要留给 AI 主干知识。

## 一个练手项目（自带验收）

写一个"日志摘要器"：读取 nginx 错误日志 → 并发调用大模型 API 摘要归类 → 输出报告。

验收标准：

- 并发上限可控（信号量），失败请求有重试，总耗时有统计
- 有虚拟环境、有类型提示、有 pytest 用例
- 这个项目的代码，将来可以直接放进你的面试作品集

## 常见坑

- 在系统 Python 里直接 `pip install`：会污染系统环境，永远用虚拟环境。
- 用同步循环串行调 100 次 API：一次调用 3 秒就是 5 分钟，异步并发后只要十几秒。
- 把 API Key 写进代码提交：密钥泄露是真实的安全事故，用环境变量。
