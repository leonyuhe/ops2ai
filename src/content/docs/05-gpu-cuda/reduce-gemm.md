> 这两个算子是 CUDA 面试和性能工程的双璧：Reduce 教会你并行归约的思维，GEMM 教会你数据复用的极限操作。更重要的是它们展示同一套方法论：先找瓶颈层级，再逐级优化。

## Reduce：把一个数组加成一个数

### 第 0 级：朴素实现

每个线程加一段再原子加到全局——原子操作成为串行点，性能惨淡。**瓶颈：全局同步。**

### 第 1 级：共享内存 + 树形归约

Block 内先把数据搬进共享内存，然后折半相加：第 1 轮 256 个线程各加一对，第 2 轮 128 个……log₂(n) 轮完成。**瓶颈从原子操作变成线程利用率——一半的线程第一轮后就闲置了。**

### 第 2 级：消除闲置 + 处理 bank conflict

让第一轮每个线程就加两个相距 blockDim 的元素（线程数减半但人人有活），地址步长错位避免 bank conflict。

### 第 3 级：Warp Shuffle

归约到只剩 32 个元素时，不再走共享内存 + `__syncthreads()`，改用 `__shfl_down_sync`——Warp 内寄存器直接交换，一条指令完成，无同步开销。

### 第 4 级：多级归约 + 向量化加载

单 block 处理更多元素（每线程先串行加 4-8 个）、float4 向量化加载减少访存指令数、block 间结果用第二轮 kernel 或原子收尾。

### 方法论沉淀

每一级优化都回答同一个问题：**当前最贵的资源是什么？**（原子竞争 → 线程闲置 → 共享内存冲突 → 指令数）。性能工程不是背技巧，是重复"测量 → 找瓶颈 → 消除"这个循环。

## GEMM：矩阵乘的极限操作

朴素 GEMM 每个线程算一个输出元素，每个元素重复从全局内存读整行整列——C=A×B 中 A 的每个元素被读 N 次，带宽灾难。

### 核心武器：Tiling（分块）

把矩阵切成小方块（tile，如 128×128），每次把一对 tile 搬进共享内存，block 内线程在片上完成这块的所有乘加，再搬下一块。**A 的每个元素从全局只读一次，在共享内存里被复用 128 次**——HBM 访问量降两个数量级。

类比：搬一整面墙的砖 vs 用小推车分趟搬到工作台再砌。共享内存就是那个工作台。

### 进阶手段（了解层次）

- 寄存器 tiling：每个线程再负责 8×8 微块，寄存器级复用。
- 向量化加载：float4 一次取 4 个。
- 双缓冲：计算当前 tile 的同时异步预取下一个 tile，访存与计算重叠。
- Bank conflict 消除：tile 数组加 padding。

## 为什么学这两个算子

1. 它们是面试手写题的最高频选手。
2. 它们的思想直接通向 FlashAttention——FlashAttention 本质上就是"把 attention 当 GEMM 一样 tiling + 用 online softmax 避免物化中间矩阵"。
3. 它们让你对"为什么 cuBLAS/cuDNN 比自己写的快几十倍"有体感——性能工程是有方法论的体力活。

## 动手清单

1. 朴素 Reduce 跑一遍，记录耗时。
2. 逐级加入：共享内存 → warp shuffle → float4，每级记录加速比。
3. 用 Nsight Compute 对比朴素版和优化版的"内存吞吐/算力利用率"曲线——亲眼看到瓶颈迁移。
