> GPU 用"超卖线程"来掩盖访存延迟——这和操作系统用多进程掩盖 IO 等待是同一个思想。占用率就是超卖的程度。

## Warp：32 线程的统一行动班组

SM 调度执行的最小单位不是线程，而是 Warp（32 个线程一组）。同一 Warp 的 32 个线程**在同一拍执行同一条指令**（SIMT 模型），只是各自操作不同的数据。

直接推论：

- block 大小必须是 32 的倍数，否则尾部 Warp 不满员，白占资源。
- 32 个线程步调一致 → 无法各自走不同分支而不付代价，这就是分支分化。

## 分支分化（Divergence）

```cpp
if (threadIdx.x % 2 == 0) { /* 路径 A */ }
else                      { /* 路径 B */ }
```

同一 Warp 里一半线程走 A、一半走 B 时，硬件的做法是：**先执行 A（B 的一半闲置），再执行 B（A 的一半闲置）**——两条路径串行执行，耗时相加。

对策：让分支条件按 Warp 对齐（如 `threadIdx.x / 32` 而不是 `% 2`），或者干脆用无分支写法（查表、谓词化）。

## Occupancy：SM 的"在岗率" ★

定义：SM 上实际驻留的活跃 Warp 数 ÷ 理论最大值（如 64）。

为什么重要：GPU 隐藏访存延迟的方法是"这个 Warp 等数据时，立刻切到另一个就绪的 Warp 执行"。驻留 Warp 越多，调度器手里可换的牌越多，延迟藏得越干净。

占用率被三个资源上限卡住，取最小的那个：

- 每 SM 最大 block/Warp 数（硬上限）
- 每 SM 寄存器总量 ÷ 每线程用量
- 每 SM 共享内存总量 ÷ 每 block 用量

**常见误区：占用率越高越好？不一定。** 100% 占用率的 kernel 可能不如 50% 占用率但每线程干活多的 kernel。占用率是"延迟隐藏能力"的指标，不是性能本身——有些算子（如精心分块的 GEMM）故意用更多寄存器换更少访存，低占用率反而更快。判读姿势：占用率低 + 性能差 → 优化占用率；占用率低 + 性能好 → 别动它。

## 延迟隐藏账本（Roofline 的微观版）

一条全局内存加载约几百拍延迟。如果 SM 上驻留足够多的 Warp，每个 Warp 发射一条访存指令后，调度器能切换到其他 Warp 继续算，几百拍就被填满了。估算口诀：需要的活跃 Warp 数 ≈ 访存延迟 × 每拍发射指令数 的比例关系——这正是 Occupancy 数值的工程含义。

## 工具与排障

- `cudaOccupancyMaxActiveBlocksPerMultiprocessor` 可以编程查询理论占用率。
- Nsight Compute 的 Occupancy 页签直接给出三个资源中哪个是瓶颈（registers / shared memory / block size）。
- 症状"kernel 逻辑简单但慢"：先查占用率，再查访存合并。
