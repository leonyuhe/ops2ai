> CPU 是一台全能但人手少的办公室；GPU 是一座有上万名工人但每名工人只会简单工序的工厂。理解这座工厂的组织结构，是理解一切 GPU 性能问题的前提。

## GPU 与 CPU 的设计哲学分野

CPU 把晶体管花在"让每个核心更聪明"上：大缓存、分支预测、乱序执行。GPU 把晶体管花在"让核心数量更多"上：砍掉花哨控制逻辑，堆几千个简单核心。

推论：

- 串行、分支复杂的逻辑 → CPU 赢。
- 大规模、同构、可并行的数值计算（矩阵乘）→ GPU 赢，且领先一到两个数量级。
- 大模型训练和推理恰好是后者，这就是 GPU 成为 AI 时代"硬通货"的原因。

## SM：GPU 的车间

GPU 的基本生产单位是 SM（Streaming Multiprocessor，流式多处理器）。一张 H100 有 132 个 SM，每个 SM 内有：

- **CUDA 核心**：执行整数/浮点运算的工人。
- **Tensor Core**：矩阵乘专用流水线（后面详谈）。
- **寄存器文件**：每个 SM 约 256KB，是速度最快的存储。
- **共享内存（Shared Memory）**：每个 SM 约 228KB 的片上高速暂存区，由程序员手动管理——CUDA 优化的核心战场。
- **调度器**：以 Warp（32 线程一组）为单位派活。

类比记忆：SM = 车间，Warp = 班组（32 人统一行动），共享内存 = 车间内的公共工作台，寄存器 = 工人手边的工具位。

## 显存层级：性能问题的一半答案在这里 ★

从快到慢、从小到大：

| 层级 | 容量量级 | 延迟 | 带宽 | 谁管理 |
| --- | --- | --- | --- | --- |
| 寄存器 | 每 SM 256 KB | 1 拍 | 极高 | 编译器 |
| 共享内存 | 每 SM ~228 KB | 几十拍 | ~20 TB/s 级 | 程序员 |
| L2 缓存 | 几十 MB | 几百拍 | ~10 TB/s 级 | 硬件 |
| HBM 显存 | 80 GB（H100） | 上千拍 | ~3.35 TB/s | 程序逻辑 |
| 主机内存（经 PCIe/NVLink） | TB 级 | 微秒级 | 几十~几百 GB/s | 程序员 |

**黄金法则：算得快不如喂得快。** HBM 带宽 3.35 TB/s 听起来很快，但 H100 的算力是 989 TFLOPS（BF16）——算力与带宽之比（算术强度拐点）约 295 FLOP/字节。凡是"每读一个字节算不了 295 次"的算子，性能都被带宽锁死，算力再高也是空转。这就是 Roofline 模型的全部直觉，也是 Decode 阶段慢的根本原因：每生成一个 token 要把全部权重从 HBM 读一遍，计算量却很小。

## Tensor Core：专为矩阵乘而生的流水线

普通 CUDA 核心一次算一个乘加；Tensor Core 一次算一小矩阵块（如 16×16×16 的乘加）。从 Volta 架构引入后，每一代的矩阵乘吞吐都在翻倍：

- V100（FP16）→ A100（+TF32、结构化稀疏）→ H100（+FP8、Transformer Engine）→ B200（+FP4）
- 精度每降一档，吞吐大约翻一倍——这是"量化为什么快"的硬件根源。

运维推论：买卡时 Tensor Core 代际比核心数重要；跑 FP16 模型在只支持到 FP16 的老卡上，永远跑不出新卡的性价比。

## 互联：单机 NVLink 与跨机 RDMA

- **NVLink/NVSwitch**：单机 8 卡全互联，带宽 900 GB/s 级（H100）。张量并行这类高频通信只能发生在 NVLink 域内。
- **跨机**：InfiniBand/RoCE（RDMA），200-400 Gbps 级——比 NVLink 低一个数量级以上。
- 这就是并行策略的物理约束：TP 留机内，PP/DP 跨机。硬件拓扑决定软件架构，不是反过来。

## 排障速查

- 算子慢但 GPU-Util 显示 100%：可能是带宽打满（看显存带宽利用率而非 Util）。
- 多卡训练扩展效率差：先查是 NVLink 还是 PCIe 互联（`nvidia-smi topo -m`）。
- 新模型要求 FP8：先确认卡的代际（H100 及以上才完整支持）。
