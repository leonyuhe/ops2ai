> 数据并行的故事是一条清晰的演进线：DDP 解决"多卡加速"，ZeRO/FSDP 解决"单卡装不下"。看懂演进逻辑比记住名词重要。

## DDP：多卡加速的标准答案

每卡一份完整模型 + 不同数据分片，反向传播时梯度做 AllReduce 求平均，各卡同步更新。

- **优点**：实现简单、扩展性好（Ring AllReduce 通信量与卡数无关）。
- **死穴**：每卡必须装下完整模型状态（16P 字节账本）——13B 以上直接出局。
- 工程细节：梯度同步与反向计算重叠（梯度分桶，算完一桶传一桶），通信时间被藏起来大半。

## ZeRO：把冗余切片 ★

洞察：纯 DP 下每卡存的是**一模一样**的三份状态（优化器状态、梯度、权重）——N 份冗余。ZeRO 的思路：状态切片分散存储，用时再临时拼。

| 级别 | 切什么 | 每卡状态显存 | 通信代价 |
| --- | --- | --- | --- |
| ZeRO-1 | 优化器状态 | 4P + 2P + 8P/N | 与 DDP 相同 |
| ZeRO-2 | + 梯度 | 4P + 2P/N + 8P/N | 略增 |
| ZeRO-3 | + 权重 | 全部 ÷N | 每层前/反向都要 AllGather 权重 |

直觉类比：从"人手一本完整账本"到"账本分布式存储，查账时临时拼页"。

## FSDP：ZeRO-3 的 PyTorch 原生实现

FSDP（Fully Sharded Data Parallel）按层分片：

1. 每层计算前，AllGather 把该层权重从各卡拼全
2. 算完前向/反向，立刻释放拼来的权重副本
3. 梯度 ReduceScatter：归约的同时直接分片，每卡只留自己那片

任意时刻单卡只持有"自己那 1/N 的全部状态 + 当前一层的完整权重"。70B 模型在 64 卡上，静态显存从 1.12 TB 压到每卡约 18 GB——账本立刻变得可行。

## 选型决策树

1. 模型状态装得进单卡（16P < 单卡显存）→ **DDP**，最简单最快。
2. 装不下 → **FSDP/ZeRO-3** 为默认选择。
3. 仍然不够（万亿参数级）→ FSDP + TP + PP 组合，见并行策略全景一文。
4. 显存极紧但卡间带宽差 → ZeRO-Offload（状态卸载到主机内存），用 CPU 内存和通信换可行性。

## 运维关注点

- FSDP 的 AllGather/ReduceScatter 都在关键路径上——跨机带宽不足时 FSDP 训练扩展效率会先崩，扩容前先跑 nccl-tests。
- checkpoint 保存：FSDP 的权重是分片的，保存时要聚合（或存分片格式），加载脚本要和保存格式匹配——生产事故高发区。
- 训练中断恢复：checkpoint 完整性校验、按需加载（lazy load），和你的数据备份纪律一致。
