> 单轮 LLM 调用看日志就够了；多步 Agent 需要真正的分布式追踪——一次任务几十次模型调用加几十次工具调用，没有 trace 就是盲人摸象。

## Trace：Agent 的调用链

每次任务执行是一棵调用树：

```
任务 span
├── LLM 调用 span（模型、输入摘要、token 数、耗时）
├── 工具调用 span（工具名、参数摘要、结果状态、耗时）
├── LLM 调用 span
└── ...
```

要点：

- 每个 span 记录 token 用量与耗时——成本与延迟归因全靠它。
- 输入输出记录**摘要**而非全文（全文进安全存储，trace 里放引用）。
- 任务级打标签：用户、场景、成功/失败、步数——聚合分析的维度。

开源方案：Langfuse、OpenLLMetry/OpenInference（OTel 系）都能直接接进你现有的可观测性栈。

## 三个 Agent 特有的监控指标 ★

1. **步数分布**：任务平均几步完成？步数 p99 是多少？步数膨胀通常意味着工具不好用或模型变笨。
2. **工具失败率**：按工具分列——某个工具失败率突增，多半是上游 API 变了。
3. **单任务成本**：Σ（各 span 的 token 成本 + 工具成本）。Agent 的成本方差极大，必须按任务归账，否则月底账单无法解释。

## 人工接管（Human Handoff）

Agent 的"转人工"就是运维的"升级值班"：

- 触发条件：连续失败、预算耗尽、涉及高风险动作、用户主动要求。
- 交接质量：把 trace 摘要（目标、已做步骤、卡在哪）一起交接，人不需要从头读几十条记录。
- 接管率本身是关键指标——骤降可能是事故（该转的没转），骤升可能是模型退化。

## 失败回放与评估

- 失败任务的 trace 导出成评测样本，修复后进回归集——**每次生产事故都转化为测试资产**。
- 离线评估：用录制回放（固定工具响应）重跑 Agent，验证修复有效且不回归。
- 这套"事故 → 用例 → 回归门禁"的闭环，和你做故障复盘后补监控的纪律完全同构。

## 告警建议

- 即时告警：单任务成本超限、工具错误率飙升、步数 p99 异常。
- 日报/周报：任务成功率、平均步数、成本构成、接管率趋势——Agent 系统的退化是渐变的，周环比比阈值告警更能发现问题。
