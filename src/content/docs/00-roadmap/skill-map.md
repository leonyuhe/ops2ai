> 一句话结论：大模型时代没有淘汰运维，而是把运维的核心能力平移到了 AI 基础设施上。

## 总览对照表

| 你的运维经验 | AI Infra 里的对应物 | 迁移难度 |
| --- | --- | --- |
| Linux 系统调优（CPU/内存/IO） | GPU 服务器调优（显存、NVLink、NUMA 亲和） | ★ 低 |
| Prometheus/Grafana 监控告警 | LLM 服务可观测性（trace、TTFT/TPOT、token 成本） | ★ 低 |
| 容量规划与压测 | GPU 容量规划、推理吞吐/延迟预算、并发压测 | ★ 低 |
| K8s 编排与调度 | 模型推理服务编排、GPU 调度与配额管理 | ★★ 中低 |
| CI/CD 流水线 | MLOps：模型评测、灰度发布、回滚门禁 | ★★ 中 |
| Shell/自动化脚本 | Python 工程化、数据处理管道 | ★★ 中 |
| 故障排查方法论 | 训练 loss 发散排查、p99 延迟归因 | ★★ 中（方法论完全复用） |
| 网络架构（TCP/IP、负载均衡） | RDMA/NCCL 集合通信、推理网关路由 | ★★★ 中高 |
| 存储系统 | 训练 checkpoint 管理、向量索引存储 | ★★★ 中高 |
| 全新知识 | 模型原理、CUDA、并行策略 | ★★★★ 需要系统学习 |

## 三类平移方式

### 直接平移：改个名字就是你的活

监控告警、容量规划、故障排查、发布流程——这些能力在 AI 系统里一字不改地需要。AI 团队最缺的往往不是会写 kernel 的人，而是**能让服务稳定跑在生产上的人**。这恰恰是你的主场。

### 类比平移：概念换皮，骨架不变

举三个例子：

- **负载均衡 → LLM 网关路由**：你在 Nginx 里按权重分流的经验，换成按模型成本/延迟/能力分流，思想完全一致。
- **磁盘配额 → KV Cache 显存预算**：推理服务的显存大头是逐请求的 KV 缓存，做容量规划的逻辑和你算磁盘增长一模一样。
- **JVM GC 调优 → 推理引擎调度调优**：都是"吞吐 vs 延迟"的权衡，都有批处理大小这个旋钮，都会遇到长尾。

### 需要硬学：全新知识层

模型原理、CUDA 编程、分布式并行策略——这些没有运维对应物，必须系统学。好消息是：它们有成熟的学习路径，且你不需要学到研究员深度，工程岗要求的是"理解机制 + 会做取舍"。本站的模块二、三就是为此设计的。
