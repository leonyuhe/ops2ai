> 老板迟早会问："这个 AI 功能一个月烧多少钱？"能当场算清这笔账，你就从"会用 AI"升级成了"懂 AI 工程"。

## 成本的三层账

### 第一层：显存账（装不装得下）

单实例需要的显存 = 权重 + KV Cache 池 + 激活与工作区：

- 权重：参数量 × 字节数（7B FP16 = 14 GB，INT4 = 3.5 GB）
- KV Cache 池：引擎启动时按剩余显存分配，决定并发上限
- 例子：一张 24 GB 的卡跑 7B FP16（14 GB 权重），剩约 10 GB 给 KV Cache——上下文 4K 时大约支撑几十路并发。

### 第二层：吞吐账（一张卡每秒出多少 token）

Decode 阶段吞吐 ≈ 显存带宽 ÷ 每 token 搬运的字节数 × 并发效率：

- 直觉公式：单卡 decode 吞吐大致与"权重字节数"成反比——7B FP16 在消费级卡上几十 token/s，INT4 后接近翻倍再翻倍。
- 批处理把单流吞吐放大 N 倍（N = 有效并发），但有饱和拐点。

### 第三层：单价账（每百万 token 多少钱）

```
每 token 成本 ≈ 卡时单价 ÷ (吞吐 × 利用率)
```

一张 H100 卡时约 2-4 美元，7B 模型高吞吐跑起来每百万 token 成本可以低到几毛钱人民币；但换成 70B、低并发、长上下文，成本立刻翻几十倍。**模型大小、并发利用率、上下文长度是成本的三个乘数。**

## 降本杠杆清单（按性价比排序）

1. **换小模型**：任务允许的话 7B 换 70B，成本降一个数量级——先问业务要不要那么大的模型。
2. **量化**：FP16 → INT4，显存和速度双赢。
3. **提高并发/批处理**：同一张卡多塞请求，摊薄卡时成本。
4. **前缀缓存**：多轮对话和固定 system prompt 场景，省 prefill 算力。
5. **思考预算**：推理模型限制思考长度，直接砍输出 token 数。
6. **路由分级**：简单问题走小模型，难题才上大模型（LLM 网关）。

## 一个估算练习

场景：内部知识库问答机器人，500 员工，日均 50 次问答/人，每次问答平均输入 2000 token、输出 300 token。

- 日 token 量：500 × 50 × 2300 ≈ 5750 万 token/天
- 选 7B INT4 模型：单张 L40S 级卡高并发下可支撑，日卡时成本百元级
- 若选云端 70B API：按市场价估算可能数千元/天

结论：这个量级自建小模型完胜。**成本核算的结论经常反直觉，算完再决策。**
