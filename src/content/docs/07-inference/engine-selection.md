> 引擎选型没有"最好"，只有"最匹配你的负载画像和团队栈"。本文给一个可复用的对比框架。

## 三引擎速写

### vLLM：生态之王

- 开源社区最大、模型支持最快（新模型当天支持是常态）、生产验证最广泛。
- PagedAttention、连续批处理、前缀缓存、Chunked Prefill、投机解码、多机 TP/PP——功能全。
- 适合：绝大多数自建推理服务的默认起点。

### SGLang：复杂 LLM 程序之王

- RadixAttention 前缀共享 + 原生结构化输出 + 前端编程语言。
- Agent、多轮工具调用、JSON 约束输出场景的性能与可靠性优势明显。
- 适合：Agent 平台、重度结构化输出、复杂调用链。

### TensorRT-LLM：NVIDIA 硬件的极限性能

- NVIDIA 官方，kernel 级深度优化：FP8/FP4、In-flight batching、CUDA Graph 全用满。
- 同硬件上极限吞吐常常最高，但模型适配与工程链路更重（编译、插件、版本绑定）。
- 适合：固定模型 + NVIDIA 全系硬件 + 追求极限成本的规模化服务。

## 选型决策树 ★

1. 模型很新或经常换 → **vLLM**（适配速度就是命）。
2. 负载是 Agent/多分支/强结构化输出 → **SGLang**。
3. 模型固定、规模巨大、NVIDIA 全栈、有专职性能工程师 → **TensorRT-LLM**。
4. 拿不准 → vLLM 起步，网关层做好抽象，保留换引擎的能力。

## 对比验证的标准姿势

选型别读文章下结论，用你自己的负载做对照实验：

1. 固定同一模型、同一硬件、同一负载回放（真实 prompt 分布采样）。
2. 阶梯加压测"并发 → TTFT/TPOT/吞吐"曲线，画在同一张图上。
3. 记录 KV Cache 容量、前缀命中率、接受率（如开投机）等引擎特色指标。
4. 结论按"在 SLO 约束下谁的有效吞吐（goodput）高"裁决。

## 别忘了第四代选项

云端托管 API（不建引擎）在某些阶段是最优解：流量小、波动大、没有专职 Infra 人力时，按 token 付费可能比养 GPU 集群便宜得多。**自建的前提是规模和专业度都到位**——把账算给老板看，而不是反过来。
