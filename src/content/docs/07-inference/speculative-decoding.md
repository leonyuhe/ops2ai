> 投机解码（Speculative Decoding）是推理加速里最精巧的技术：让一个便宜的小模型先猜，大模型只做批改——既快又保证质量分毫不差。

## 问题：Decode 的串行瓶颈

Decode 每步只生成一个 token，每步都要把全部权重从显存搬一遍。搬权重的钱只产出一个 token——带宽利用率极低的串行循环。

## 核心思想：一次验证多个 token ★

关键观察：大模型**一次前向可以并行验证一整个候选序列**（和 prefill 同理），成本和生成一个 token 几乎相同（都是搬一遍权重）。于是：

1. **Draft（打草稿）**：小模型（或简易方法）快速猜出 k 个候选 token。
2. **Verify（批改）**：大模型一次前向，并行计算这 k 个位置的正确分布。
3. **接受/拒绝**：逐个比对——候选与大模型分布一致则接受；遇到第一个不一致的位置，用大模型的正确 token 替换，其后候选全部作废。
4. 从接受的最长处继续下一轮。

理想情况一轮接受 3-4 个 token，decode 提速 2-3 倍。

## 为什么质量无损（保分布证明的直觉）

接受准则不是"小模型猜得对不对"，而是经过精心设计的**残差采样**：被拒绝的位置，从"大模型分布 − 小模型分布"的残差分布中采样修正。数学上可以证明最终输出分布与大模型独自逐 token 采样**严格相同**——不是近似，是等价。这是投机解码能进生产系统的理论基础。

## 草稿方案的选择

| 方案 | 做法 | 特点 |
| --- | --- | --- |
| 独立小模型 | 同家族小档（如 70B 配 7B） | 接受率高，但要维护两个模型 |
| N-gram/后缀匹配 | 从当前上下文历史里匹配续写 | 零模型成本，代码/重复文本场景奇效 |
| Medusa | 大模型上加多个预测头，一次预测多步 | 无第二模型，头要额外训练 |
| EAGLE | 在特征层面做自回归草稿 | 当前接受率最高的主流方案之一 |
| MTP | 训练时就让模型学多 token 预测（DeepSeek-V3） | 训练推理一体设计 |

## 收益边界：什么时候不帮忙 ★

- **高并发时**：GPU 已被大批次打满（compute-bound），带宽不再是瓶颈，投机反而增加计算量——它加速的是低并发/单流场景。
- **草稿接受率低时**：模型与草稿分布差异大（如创意写作 vs 通用草稿模型），大部分候选被拒，白算。
- **输出很短时**：验证开销收不回。
- 工程上要按接受率指标动态开关或调候选长度。

## 运维关注点

- 监控**平均接受长度**（accepted tokens per step）：这是投机解码健康度的唯一真相指标。
- 草稿模型/方法也算容量：它要占一份显存和算力，容量规划时别漏。
- 流式输出下投机解码与 chunk 推送的交互要实测，首 token 延迟可能变差。
