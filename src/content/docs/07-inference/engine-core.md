## 一、PagedAttention：KV Cache 的显存管理 ★

### 问题

朴素实现为每个请求按"最大可能长度"预分配连续显存：一个最大 4K 的请求哪怕只聊了 10 个字，也占着 4K 的位置。结果是：

- 内部碎片：预留没用掉的部分
- 外部碎片：不同长度请求释放后留下的窟窿
- 实测：朴素管理下 60-80% 的 KV 显存被浪费

### 思想：操作系统的虚拟内存分页

- KV Cache 切成固定大小的**块（block，如 16 token/块）**，逻辑上连续、物理上可不连续。
- 每个请求维护一张**块表（Block Table）**——就是页表，记录逻辑位置 → 物理块的映射。
- 请求增长时按需分配新块；结束即回收。

收益：碎片浪费从 60-80% 降到 4% 以内，同等显存下并发容量数倍提升。

### 两个附赠能力

- **前缀共享**：多个请求共享相同前缀（如系统 prompt）时，块表指向同一份物理块，引用计数 + **Copy-on-Write**（有人要改才复制）。这就是前缀缓存的底层支撑。
- **Beam search/多采样**：n 个候选序列共享父序列的块，天然省显存。

## 二、连续批处理（Continuous Batching）★

### 问题：静态批处理的"班车病"

静态批处理凑满一批一起跑、跑完才放下一批。批内各请求长度差异巨大——最快的 50 token 就完事，最慢的要 2000 token。班车病：全车等最慢的乘客，GPU 在收尾阶段大半空转。

### 思想：迭代级调度（流水席）

每次 decode 迭代都重新编组：

- 某请求本轮生成完毕 → 立刻下车，不等别人
- 新请求到达 → 下一个迭代即可上车

GPU 永远满编运转。实测效果：吞吐量相对静态批处理提升 2-8 倍（工作负载越杂提升越大），GPU 利用率从约三成拉到八成以上。

### 调度器要回答的问题

- 显存满了新请求怎么办？——排队（waiting 队列）。
- 来了高优先级请求显存不够？——**抢占**：把某些请求换出（重算或 swap 到内存），稍后恢复。
- Prefill 和 Decode 怎么混排？——见第四节。

## 三、前缀缓存（Prefix Cache / RadixAttention）

### 问题

多轮对话每轮都把全部历史重新 prefill 一遍；所有请求都带同一个 system prompt 也重复计算。重复 prefill 是纯浪费。

### 思想：KV Cache 的内容寻址复用

- vLLM 路线：按块内容的哈希做键，相同内容的前缀块直接命中缓存（自动前缀缓存）。
- SGLang 路线：Radix Tree（基数树）组织缓存，支持任意前缀匹配，共享更灵活。

注意点（生产必知）：

- **前缀必须逐 token 一致**：system prompt 改一个字、对话历史中间插一句，缓存全部失效——prompt 工程要"稳定前缀、变化后置"。
- 缓存容量有限，有淘汰策略（LRU）。
- 命中率的监控是核心指标：prefix cache hit rate 低而 TTFT 高，优先查 prompt 结构。

## 四、Chunked Prefill 与统一调度

### 问题：Prefill 和 Decode 互相干扰

一个 8K token 的长 prompt 做 prefill 要几百毫秒——这期间同批的 decode 请求全部被卡住，正在聊天用户的 TPOT 突然飙升（打字卡顿感）。

### 思想：把长 prefill 切成块，和 decode 混编

- 每个调度步设定 **token 预算**（如 2048）：decode 请求各出 1 个 token，剩余额度给 prefill 的下一个块。
- 长 prefill 被切成多步完成，decode 请求只被"让路"一小会儿而非卡住几百毫秒。

收益：TTFT 略升（prefill 被拉长），但 TPOT 平稳、尾延迟（p99）大幅改善——混合流量下用户体验的关键优化。vLLM V1 已把 prefill/decode 统一进同一调度器，边界彻底抹平。

## 四技术的协同关系

PagedAttention 解决"显存怎么管"，连续批处理解决"请求怎么排"，前缀缓存解决"重复怎么省"，Chunked Prefill 解决"长短怎么混"。四者合力，才把 GPU 从"单 request 串行推理"改造成"高并发推理服务"。这也是读 vLLM/nano-vllm 源码的四条主线。

## 面试速记

- PagedAttention = 分页 + 块表 + 引用计数 + COW，碎片率从 60-80% 降到 4% 内。
- 连续批处理 = 迭代级重编组，完成即退、随到随上。
- 前缀缓存失效条件：前缀必须逐 token 一致。
- Chunked Prefill = token 预算内长短混编，牺牲一点 TTFT 换 TPOT 平稳。
